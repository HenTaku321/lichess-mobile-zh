# 象棋集成交互审查与整改

## 目标与执行约束

基准是同一版本的 Lichess App；保留象棋规则、九路十行和现有棋子材质。
按棋盘/对局、分析/复盘、其他页面三批推进，区分源码发现、运行复现和验收。
Flutter 测试、分析、codegen 和编译使用 GitHub Actions，不在本机编译，不开子代理。
本机可做格式/diff 检查，并运行既有 Linux 二进制；运行检查使用隔离的测试配置。

## 已确认的审查基线

源码和已发布 Linux 包均对应 `34024fcff`；该提交的全量 Tests 和 Linux 构建已通过。
既有回归没有 golden、逐页截图或移动端声音/触觉验收，因此不能声明全量 UI 一致。

## 第一批实施步骤

1. 新增 `xiangqi_history_parity_test.dart`，通过假 transport 驱动真实页面，再执行长按手势。
2. 在独立分支的 Actions 中验证失败确实是上述差异，而非 fixture 或加载失败。
3. 复用已有 `RepeatButton` 和 `BottomBarButton`，统一 tooltip、禁用态和历史按钮标签。
4. 在线重复动作读取当前 cursor；轮到我方时显示返回实时局面的提醒；浏览不得发出走子。
5. 检查抵达两端、松手、实时帧到达和页面销毁后的定时器与状态，不改动真实对局历史。
6. 通过分组及全量回归后，才交付本批结果；后续批次继续追踪动画、反馈和复盘数据。
