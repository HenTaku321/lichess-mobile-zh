# 象棋 UI 全流程共用与一致性整改

基线：生产源码 `4d0a7d79a`，工作分支 `fix/xiangqi-desktop-parity`。
用户已批准共用国象界面层，并补齐本地可实现的交互。

## 约束

不开子代理，不在本机编译、测试、analyze 或 codegen；本机只编辑、format 和静态检查。
验证交给 Actions。不读取/修改 mihomo、个人密钥或宿主设置；清理移入回收站，不使用 rm。
Linux 是主验收平台，Android/iOS 做兼容回归。不自动安装或覆盖现有发布包。

## 实施顺序

1. 共用棋种无关的反馈、玩家行、评估呈现、菜单和布局；两种棋盘通过薄适配层接入。
   沿用现有主题、字体和交互时序，禁止把象棋局面伪装成 dartchess.Position。
2. 人机/OTB：对齐菜单、终局分析、历史浏览、新局和设置确认。
3. 分析/复盘/编辑器/数据库：完整历史输入、独立来源会话、非破坏式分支及继续此局面。
   路由增加初始 FEN、着法、光标、视角、来源和引擎权限；保留已有 FEN 入口兼容。
4. 在线/观战：菜单在前、历史在后，按真实能力显示动作；覆盖预走、重连和回实时。
5. 谜题/课程：共用正确/错误/完成反馈，跨自动回复或回退保留；保存状态与解题结果分离。
   完成后可浏览和分析已展示的历史，不重复提交、不绕过额度。
6. 全入口：列表、保存、好友、排行、比赛、账号、资料、通知、私信、聊天室及其预览/弹窗。
7. 共享 Pikafish 搜索明确所有权；离页暂停，回同一棋局恢复待评分/回复阶段，拒绝迟到结果。
8. 各组 Actions 红回归→最小实现→绿回归，最终同 SHA 全量测试、原生回归与 Linux 构建。

## 验收

每组使用真实 controller/provider，只模拟 HTTP/Socket/引擎传输边界。
国象/象棋同阶段配对截图覆盖 480×480、1280×720、1920×1080，深浅主题、中英文、1×/2×。
严格检查 overflow、键盘/鼠标状态及操作可达性；逐组检查图片，不把截图生成当作视觉一致。
平台/上游必要差异明确列出；声音、触觉没有实际证据时标为未验收。
