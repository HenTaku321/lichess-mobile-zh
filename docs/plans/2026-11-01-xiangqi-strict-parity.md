# 象棋集成：严格对齐国象体验实施计划

目标：沿用现有国象设计，完成主流程和剩余入口的一致性，不重新设计国象。
架构：棋种无关呈现由共用组件负责，棋盘、规则、记谱和协议由薄适配层提供。
技术：Flutter / material_ui、Riverpod、不可变棋谱树；测试与构建仅在 Actions 执行。

## 约束

- 复用 `mobile-xiangqi-parity` / `fix/xiangqi-desktop-parity` 工作树，不开子代理。
- 本机只编辑、format 和检查 diff，不编译、测试、analyze 或 codegen。
- 不碰 mihomo、个人密钥或宿主设置；废弃文件移到回收站，不使用 rm。
- 保留国象的外部棋盘 controller 和 Crazyhouse pockets；不伪装象棋局面为国象类型。
- 真实上游没有的能力不显示，不猜请求。进行中在线棋局不新增引擎分析入口。

## 分批执行

1. 对局呈现：提取共用布局、玩家信息行、评估条；接入两种棋。覆盖紧凑横屏、
   字号缩放、时钟位置、翻转、禁用状态；菜单排序及能力判断由共用呈现契约控制。
2. 分析棋谱：从国象 PGN 视图提取泛型树呈现，接入象棋完整主线/侧枝，支持双列/
   行内、折叠、滚动、高亮和节点菜单；提升一档/主线、复制和定向删除保留其他子树。
   象棋整局导出明确使用 FEN + 中文分支记谱，不冒充国象 PGN；保留旧 FEN/ICCS API。
3. 交接：人机/OTB 隔离逻辑会话及其时钟；历史评语与建议绑定所显示的局面。
   OTB 终局、复盘、数据库、完成后的谜题/课程传完整已展示历史、光标、视角、来源。
   浏览不重复提交/扣额度，不泄露未展示答案；继续此局面用当前 FEN 开独立新局。
   分析来源缓存保留树、路径、视角及折叠状态，权限贯穿编辑器/继续入口。
4. 其他入口：保存题目按 ID 打开；列表、资料、好友、保存、通知、私信、聊天室
   复用已有呈现，并验证进入、操作、返回和刷新。失败保留草稿/棋局/选择状态，
   异步操作拒绝旧账号或旧逻辑会话的结果，重试不重复执行。

## 每批验收

- 新回归先在 Actions 得到真实行为红结果，再做最小实现和绿回归。
- 使用真实 controller，只模拟 HTTP/Socket/引擎传输，不吞 overflow 或删掉失败断言。
- 逐批保留国象既有回归。两种棋同阶段配对截图覆盖 480×480、1280×720、1920×1080，
   深浅主题、中英文、1×/2×；补思考、评分、评语跨回复、历史、终局、分支及切页状态。
- 生成截图和几何检查不算主观视觉验收。无法实际审阅图片时明确记为待验收。
- 原生 Linux 操作与移动端声音/触觉没有证据时标为未验收。
- 整组验收完成后才构建同源码发布包，不自动安装。
