# 象棋剩余 UI 一致性实施计划

目标：完成课程/题目实际历史与回放交接、剩余入口，以及配对视觉和原生验收。
基线：`62afeda9b`（生产 `ead9a4571`，Actions `41307271218` success）。
架构：真实 controller 与不可变历史；棋种无关呈现复用国象组件，教学规则与对局规则隔离。

## 约束与确认

- 沿用现有工作树，不开子代理；本机只编辑、format、检查 diff，其他验证和构建在 Actions。
- 不读取 mihomo，不改宿主设置；不自动安装、不替换现有包或滚动发布，清理只移入回收站。
- 非标准课程保留完整教学回放；当前局面校验通过后可另开独立分析/人机局。
- 用户负责 iPhone 真机操作、声音/触觉验收，代理不连接或主动测试手机、不运行手机模拟器。
- 用户确认分组配对图的主观视觉；自动截图和几何检查不等于看图验收。

## 实施顺序

1. 实际课程历史：记录 `acceptedMoves`，正常/自动/多答案接受同步追加，撤销同步截断。
   棋谱、最后一步、吃子/将军反馈使用实际步骤；教学记谱按移动棋子所属方，不改局面轮次。
2. 训练回放与分析交接：新增 `XiangqiReplaySnapshot`；普通历史严格规则验证，教学历史
   验证记录的转换并只读按步骤编号。分析能力分别控制引擎、历史编辑、导出、局面分析、
   继续对局；保留旧 `line` / `engineAllowed` 兼容，缓存包含类型、权限、账号来源。
   完整线路展示后才允许训练分析；回看不影响学习进度、提交或额度，离页取消自动推进。
   教学当前局面校验数量/落点、双将/照面、计数、非行棋方被将；终局不继续对弈。
3. 其余入口：覆盖首页/Play/More/Hub/账号入口到资料、棋局、好友、保存、排行、赛事、
   观战、通知、私信和聊天室；复用已有呈现，保留独立协议与分页。双击/返回/刷新/失败/
   换号保持本账号有效内容，拒绝旧结果；已确认的站内链接内部路由，其他 HTTP(S) 外开。
4. 验收基础设施：Actions 分组生成同状态配对图（480×480 / 1280×720 / 1920×1080，
   深浅、中英、1×/2×）。Linux 原生窗口/插件/输入检查采用隔离显示、D-Bus、HOME/XDG
   和音频后端；不依赖或更改宿主设置。手机测试只交付短清单，不主动执行。
5. 自动回归通过后同 SHA 构建待验收 Linux/iOS 包，不覆盖现有发布；主观视觉及用户
   真机反馈记录完成后才准备正式发布，未验收项保持明确状态。

## 验证契约

- 每组真实行为红回归 → 最小实现 → Actions 绿回归；保留国象分析/Study/解题/聊天回归。
- 使用真实 controller，仅模拟 HTTP/Socket/引擎传输；不吞 overflow、删断言或冒充原生证据。
- 覆盖多答案非脚本着法、连续同方教学、撤销、合法局面继续、非法/终局禁用出口；
  提交中/失败/成功、自动推进、返回、换账号、请求次数与实际完整 FEN。
- 视觉分组记录 loading/思考/反馈/历史/终局/分支/菜单/失败状态，提供索引和成组对照图。
